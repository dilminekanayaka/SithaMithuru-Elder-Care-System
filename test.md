# 2. PRIMARY OBJECTIVE

The objective is:

> **If this application were given to a real user tomorrow, the user should be able to use the application naturally without encountering obvious prototype behavior, disconnected screens, fake data, broken navigation, missing backend functionality, broken database operations, inconsistent UI, or unfinished workflows.**

The application must feel like **one complete product**, not a collection of separately developed screens.

---

# 3. IMPORTANT MINDSET

Do NOT think:

> "I need to finish the screens."

Think:

> "I need to finish the product."

A screen is NOT complete merely because:

- it looks good
- it renders
- it has buttons
- it has dummy data
- it has navigation
- it has placeholder cards

A screen is complete only when the required frontend, backend, database, state management, validation, error handling, offline behavior, security, and testing are properly connected.
